# 3.4 提交改动 `[required · once]`

## 目标

在最后一轮质量检查通过后，按逻辑分组提交本次任务改动。

## 执行动作

1. 用 `git status --porcelain` 检查脏状态，区分本会话改动与未识别改动。
2. 用 `git log --oneline -5` 学习提交风格。
3. 为连贯变更单元起草提交计划，不按单文件机械拆分。
4. 一次向用户展示计划并等待确认。
5. 用户确认后执行 `git add <files>` 和 `git commit -m "<msg>"`。

禁止 amend、push、绕过 hook 或将未识别的用户改动静默纳入提交。提交顺序是先工作提交，后由 `/finish-work` 处理归档和日志。

完整/普通档提交完成后，提醒用户运行 `/finish-work`（原 3.5）：该流程负责归档任务并记录 session journal，要求工作区干净。极简档没有任务可归档，跳过提醒。

## 验证标准

- 提交前最后一轮 2.2 已全范围通过（极简档为自行验证通过）。
- 用户已确认提交计划。
- 工作区达到 `/finish-work` 所需的干净状态；没有仍在运行的验证命令或未处理的错误。
