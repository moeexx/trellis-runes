# 2.3 回滚 `[on demand]`

## 目标

在实现或检查暴露问题时回到正确的阶段，避免在错误前提上继续修改。

## 路由规则

- `check` 暴露 PRD 缺陷：回 Phase 1 修订 `prd.md`，再重做 2.1。
- 实现本身出错：回退本次代码改动，重做 2.1。
- 需要更多事实：执行 1.2 研究，并将结果写入 `research/`。
- 同一 phase 连续三次修复/验证失败：运行 `task.py rollback <task> record --phase <phase>`，停止猜测式修复；请求人工介入后用 `task.py audit <task> human-gate --kind rollback-intervention --detail <detail>` 记录事实。reset 时运行 `task.py rollback <task> reset --intervention <detail>`。

`rollback record/reset` 自动写入 `lifecycle-events.jsonl` 的 `rollback` 事件；人工确认命令写入 `human-gate`。审计写入失败不会替代或阻断既有 rollback 语义，但显式 human-gate 命令失败必须重试。

## 验证标准

回滚后任务仍处于可识别的阶段，规划产物、任务状态和代码改动彼此一致。
