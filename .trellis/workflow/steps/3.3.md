# 3.3 Spec 更新 `[required · once]`

## 目标

判断本任务是否产生应长期保存的新知识，并更新相关 spec。

## 执行动作

加载 `trellis-update-spec`，评审以下内容：

- 新 pattern 或约定。
- 踩过的坑及预防措施。
- 新技术决策。

只有确实属于长期代码规范或架构知识的内容才写入 `.trellis/spec/`；工作流步骤契约写入 `.trellis/workflow/steps/`。

## 验证标准

即使结论是没有需要更新的 spec，也必须完成一次明确判断。
